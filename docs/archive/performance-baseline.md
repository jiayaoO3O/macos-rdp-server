# 性能基线采集

> **历史记录（已被取代）** — 早期性能基线；非当前基线。
> 当前状态/可用范围/测试基线/部署运行态以 [docs/STATUS-2026-11-08.md](../STATUS-2026-11-08.md) 为准。


先确认 Worker 的实际日志路径和客户端连接状态；不需要重启 Worker 或 Agent：

```sh
python3 scripts/performance-baseline.py .runtime/worker-live.log --seconds 30
```

工具从日志当前末尾开始观察，输出窗口内 Worker 收到和发出的不同
`(generation, frame_id)` 数量及每秒速率、发送事件数、源尺寸和编码。未连接客户端时
发送帧数可能为零；Agent 重启后的新 generation 会分别计数。同一帧重复发送只计一次，
多客户端的事件会合并，适合单客户端基线。日志轮转或截断时工具报错，不给出误导性结果。
工具不会输出其他日志内容或剪贴板内容。

这些数值是**服务端事件速率**，不是客户端实际显示 FPS、网络吞吐或端到端延迟；
窗口边界、日志缓冲和观察中的连接变化也会影响结果。现有运行进程不会因新增此工具改变行为。
每次对比请使用同一设备与网络、客户端版本、窗口尺寸、编码和时长，并记录：

- 客户端设备、Windows App 版本、网络与客户端实际显示尺寸；
- 画面活动内容、源尺寸、编码及工具输出；
- 客户端实测显示 FPS、交互延迟、文字清晰度与颜色；
- 双端 CPU、带宽和测量方法，以及丢帧或断连情况。

未测量的项目应标为未测量，不能由 Worker 发送帧数推断。不要记录账号凭据、剪贴板或私有日志。
真实局域网客户端验收前不得声称帧率或画质已有改善。
